# raspi-k3s-applications

This repository contains the application source code and service-specific Jenkins pipelines used in the Raspberry Pi Kubernetes Home Lab project.

The primary objective of this repository is not to demonstrate complex business logic or distributed systems design. Instead, the applications exist to provide realistic workloads for experimenting with:

* Kubernetes,
* GitOps,
* CI/CD pipelines,
* network policies,
* ingress routing,
* observability,
* container hardening,
* and deployment automation.

The platform and infrastructure concerns are intentionally prioritized over application complexity.

## Repository Structure

The repository is organized into two main directories:

* `src`
  Contains the .NET 10 application source code, Dockerfiles, and Docker Compose configuration.

* `Jenkins`
  Contains the declarative Jenkins pipelines used for building, testing, publishing, and deploying the applications.

## Applications

The following applications are included in this repository:

### Accounts API

A simple authentication service responsible for generating JWT tokens.

### Users API

A basic user registration service.

This service intentionally does not require authentication in order to simplify interaction flows during Kubernetes and networking experiments.

### Search API

Provides user search capabilities.

This API requires a valid JWT token generated by the Accounts API.

### Gateway

An API Gateway implemented using YARP.

The Gateway acts as the entry point between the Kubernetes Ingress layer and the backend APIs.

## Architecture Notes

These services communicate exclusively through REST APIs.

Although the services are separated into independent applications, this project does not currently implement a fully isolated microservices architecture:

* the services share the same PostgreSQL database,
* and the same database schema.

This is an intentional design decision.

The primary focus of the Home Lab is Kubernetes platform engineering and GitOps workflows rather than domain decomposition or distributed data management. Introducing fully isolated databases per service at this stage would increase operational complexity while providing limited value for the current objectives.

## Local Development Environment

The repository includes a Docker Compose configuration used for local integration testing.

The Compose stack orchestrates:

* all APIs,
* PostgreSQL,
* and the .NET Aspire Dashboard observability stack.

This environment allows validating the complete application flow locally before container images are built and deployed into Kubernetes.

## CI/CD Strategy

Each application has its own dedicated Jenkins pipeline.

The CI/CD implementation uses:

* declarative Jenkins pipelines,
* shared pipeline libraries,
* multibranch pipeline strategies,
* and ephemeral Kubernetes agents.

The overall Jenkins platform architecture and shared CI/CD strategy are documented separately in [`raspi-k3s-jenkins`](https://github.com/MyProgrammingProjects/raspi-k3s-jenkins).

At a high level, the workflow is:

1. source code is committed,
2. Jenkins builds the application container image,
3. the image is pushed to the container registry,
4. deployment manifests are updated in the Helm charts repository,
5. Argo CD synchronizes the Kubernetes cluster state.

## Container Strategy

The container images are built for ARM64 environments targeting Raspberry Pi nodes running Kubernetes.

The applications use Azure Linux container base images (formerly CBL-Mariner) in order to reduce container attack surface and keep runtime environments minimal.

Containers are also configured to run as non-root users as part of the platform security hardening strategy.

## Project Scope

This repository represents only the application and application-specific CI/CD layer of the Home Lab environment.

Other platform concerns are intentionally separated into dedicated repositories, including:

* Kubernetes platform configuration,
* shared Jenkins infrastructure,
* GitOps manifests,
* and Argo CD deployment definitions.

For the overall platform architecture, refer to [`raspi-k3s-platform`](https://github.com/MyProgrammingProjects/raspi-k3s-platform).
